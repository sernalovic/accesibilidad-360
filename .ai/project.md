# Proyecto

## Nombre

Accesibilidad 360

## Descripción

Accesibilidad 360 es una aplicación web colaborativa diseñada para ayudar a personas con discapacidad a localizar, consultar y evaluar el grado de accesibilidad de establecimientos públicos y privados.

La plataforma permite que la comunidad contribuya registrando establecimientos, valorando distintos criterios de accesibilidad, subiendo fotografías y compartiendo información útil para otros usuarios.

El proyecto se desarrolla como Trabajo Fin de Máster en Programación con Inteligencia Artificial.

La inteligencia artificial no forma parte del producto final. Se utilizará exclusivamente como herramienta de apoyo al desarrollo.

---

# Objetivos

Desarrollar una aplicación web moderna, mantenible y escalable que demuestre buenas prácticas de ingeniería del software.

Los objetivos principales son:

- Aplicar Specification-Driven Development (SDD).
- Desarrollar utilizando TypeScript.
- Mantener una arquitectura modular.
- Priorizar la accesibilidad desde el diseño.
- Automatizar las pruebas.
- Automatizar el despliegue.
- Mantener una documentación completa durante todo el proyecto.

---

# Alcance

El proyecto implementará un Producto Mínimo Viable (MVP) completamente funcional.

No pretende competir con plataformas comerciales ni cubrir todos los casos posibles.

Las funcionalidades avanzadas podrán incorporarse como futuras evoluciones.

---

# Público objetivo

- Personas con movilidad reducida.
- Personas usuarias de silla de ruedas.
- Personas con discapacidad física.
- Familiares.
- Asociaciones.
- Administraciones públicas.
- Cualquier ciudadano interesado en conocer la accesibilidad de un establecimiento.

---

# Funcionalidades del MVP

- Registro de usuarios.
- Inicio de sesión.
- Gestión del perfil.
- Alta de establecimientos.
- Edición de establecimientos.
- Eliminación de establecimientos (según permisos).
- Localización mediante mapa.
- Valoraciones de accesibilidad.
- Subida de fotografías.
- Búsqueda y filtros.
- Panel básico de administración.

---

# Funcionalidades futuras

Estas funcionalidades quedan fuera del alcance del TFM, pero deberán tenerse en cuenta durante el diseño para facilitar una futura ampliación:

- Favoritos.
- Gamificación.
- Moderación colaborativa.
- Estadísticas avanzadas.
- Aplicación móvil.
- API pública.
- Multidioma.
- Integración con OpenStreetMap.

---

# Filosofía de desarrollo

El desarrollo seguirá estrictamente un enfoque Specification-Driven Development.

Toda implementación deberá estar precedida por una especificación aprobada.

Nunca se desarrollará una funcionalidad sin disponer previamente de:

- Objetivo.
- Historias de usuario.
- Requisitos.
- Criterios de aceptación.
- Casos límite.
- Estrategia de pruebas.

---

# Restricciones

Durante el desarrollo deberán cumplirse las siguientes restricciones:

- No utilizar JavaScript sin TypeScript.
- No utilizar Redux.
- No utilizar jQuery.
- No utilizar CSS tradicional.
- No duplicar lógica.
- No implementar funcionalidades no especificadas.
- No introducir dependencias innecesarias.

---

# Prioridades

En caso de existir varias soluciones técnicas válidas, se priorizará aquella que:

1. Sea más sencilla.
2. Sea más mantenible.
3. Genere menos complejidad.
4. Esté alineada con Next.js.
5. Sea fácilmente testeable.

---

# Principios de calidad

Todo el código deberá ser:

- Legible.
- Modular.
- Reutilizable.
- Tipado.
- Validado.
- Testeable.
- Documentado.

---

# Documentación

Toda decisión técnica importante deberá quedar documentada.

Las especificaciones constituyen la fuente de verdad del proyecto.

El código nunca sustituirá a la documentación.

---

# Desarrollo asistido por IA

La inteligencia artificial actúa como asistente de desarrollo.

Toda propuesta generada por la IA deberá:

- Respetar la arquitectura.
- Cumplir las especificaciones.
- Incluir pruebas cuando proceda.
- Ser revisada antes de aceptarse.

La responsabilidad final del código corresponde al desarrollador.
